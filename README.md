# Miller Life 个人数据仓库

这是我的**个人数据仓库**：所有生活记录（支出、体重、睡眠、任务安排等）以开放文本形式存于此，可被**任何 AI Agent / 人在任何设备上读写**。数据永远属于我，AI 只是按需接入的"大脑"。

## 这是什么

一个以纯文本（JSON/JSONL）为核心的个人数据系统，特点：
- **数据和标准放在一起**：每个数据类型一个文件夹，里面有数据文件和「类型配置.json」
- **中文命名**：文件夹和文件都是「名称:描述」格式，人和 AI 都能一眼看懂
- **双向关联**：数据之间通过 ID 互相关联，不是孤立的表
- **统一提交入口**：所有修改通过 `tools/提交并确认.mjs` 提交，自动校验+推送
- **AI 友好**：没有黑盒数据库，任何 AI 读了 AGENTS.md 就能操作

## 目录结构

```
AGENTS.md              # 给 AI 的总入口/操作契约（唯一权威）
用户规则.json           # 用户个人操作习惯和偏好
数据检查规范.md         # 定时数据检查的标准
报表模板.md             # 早报/晚报模板
可视化规范.md           # 图表和卡片样式规范

data/                  # 所有用户数据，每个类型一个中文「名称：备注」文件夹，内含数据文件+类型配置
                       # 类型动态增减，直接列 data/ 目录或运行 数据工具.mjs types 查看，不在此枚举

收藏资料：.../          # 收藏的别人的东西（与data平级）
tools/                 # 查询/校验/提交工具
```

## AI 如何接入

1. **先读 `AGENTS.md`** — 这是给 AI 的唯一权威入口，包含启动协议、写法律、关联规则、操作规范
2. **进对应数据文件夹读「类型配置.json」** — 了解该类型的核心约束和存储路径
3. **读 `用户规则.json`** — 了解用户的个人操作习惯（如常用饮品的标准录入格式）
4. **按八步闭环写入数据** — 保存指令→确认规范→生成ID→写入→自我语义检查→同步关联→统一提交→确认结果

## 重要铁律

- **用户主动要求录入数据** → Agent 直接写入，写入后展示完整记录供核对
- **批量导入、修改历史数据、删除数据** → 必须先展示变更计划、经用户确认后才写入
- **所有 git 提交** → 必须通过 `node tools/提交并确认.mjs "提交信息"`，禁止直接 git add/commit/push
